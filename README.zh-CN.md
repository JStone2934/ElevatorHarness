# ElevatorHarness

面向面板操作的机器人 Agent 框架。核心闭环为：**全局/局部视角观察 → 面内对齐 → 沿法向接近和按压 → 确认反馈 → 撤回或重试**。

夹爪开合既改变接触构型，也改变相机视野；框架把构型、接触点和标定版本一起管理。电梯按钮是首个任务，完整乘梯导航、其他机器人真机适配和高频 VLA 控制不在第一版范围内。

## 快速体验

需要 Python 3.10+，通用包没有第三方运行依赖，也不导入机器人 SDK。

```bash
python -m pip install .
elevator-harness simulate --output /tmp/elevator-demo
elevator-harness simulate --rotated --output /tmp/elevator-demo-rotated
```

输出目录必须不存在。示例使用确定性测试机器人和脚本 Agent；第二个示例改变坐标轴、夹爪构型名称和相机可动性。它们用于验证接口与闭环，不能代表真机成功率。

## 可替换的边界

| 模块 | 职责 |
|---|---|
| Harness | 串行调度、观测绑定、重复命令检查、取消、预算与记录 |
| RobotAdapter | 设备能力、图像与状态采集、执行、停止与关闭 |
| Agent | 根据任务、观测和能力提出动作；支持端到端与定位后决策 |
| ExecutionPolicy | 显式允许或拒绝候选，不静默裁剪位移 |
| Task / Verifier | 任务进度、完成证据与独立结果判定 |

运动采用操作平面坐标 `[du,dv,dn]`，单位米；`+n` 朝向面板。S1 示例将其映射到当前 Y/Z/X，并转换为 SDK 的毫米。更换机器人要重做坐标与接触标定，不直接沿用旧设备的指端像素或距离。

`EndToEndAgent` 直接根据图像决策。`LocalizedAgent` 开爪时先做双视角粗定位，再将腕图目标区域按 3 倍范围裁剪并放大到 768 像素，进行二次定位并映射回原图。闭爪按压时切换为直接视觉决策，使用当前双图及按压前定位区域对应的当前头图 6 倍裁剪；头部姿态变化会使旧区域失效。连续微调复核、每次修正反馈和跨尝试记忆也一起保留。

图像处理需要 `pip install 'elevator-harness[vision]'`；详细流程、失败回退和配置见[感知流水线说明](docs/perception-pipeline.md)。模型地址和名称由使用者配置；接入接口必须实际支持多模态和工具调用，框架不假定某个模型的能力。

可配置按压策略包括二维重叠、开爪冻结测距、实时测距、分段接近、接触前复核、撤回和重试。构型切换后重新观察；冻结测距属于有来源记录的显式跨构型证据，不代表所有旧定位仍有效。

## S1 真机示例

见 [S1 环境、标定和启动说明](examples/s1/README.md)。先填写本地标定，再启动机器人服务和 Harness；核心 wheel 不携带 SDK 或示例硬件依赖。相机、SDK 和服务相关回归测试使用替身，不自动连接真机。

## 如何理解结果

每次运行保存图像及 `events.jsonl`：包含模型调用、候选动作、拒绝理由、发送结果、实际状态和验证结论。默认最多 40 轮，每轮最多修正 3 次，单次模型请求超时 120 秒，Agent 最多接收最近 8 条历史转换。

模型报告完成与验证器结论分别记录。视觉验证要求初始灯灭、本次亮灯、之后灯仍亮且手已离开；不确定就返回未知。即使视觉验证确认，也标记为模型判断，不冒充人工确认。二维图像重叠不等于接触，命令发送完成不等于实测到位。历史图片上的新决策没有对应的真实后果，不能据此计算闭环成功率。
